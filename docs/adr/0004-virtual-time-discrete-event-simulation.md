# ADR-0004: 仮想時間による離散イベントシミュレーション

- 状態: Accepted（2026-11-06 にプロダクトオーナーが承認）
- 日付: 2026-11-01
- 決めた人: Claude（企画書 §10.3 を具体化）
- 関連: FR-GAME-04・05、NFR-04、[DesignDoc §3・§4](../03-design-doc.md)

## 背景

フェリーの航行・手紙の配達・Raft の tick・嵐などのイベントを、一時停止や速度変更をしても矛盾なく、かつ再現できるように進める必要がある。

## 検討した選択肢

### 案 A: 仮想時間（`SimTime`）と優先度キューによる離散イベントシミュレーション

- 長所: 一時停止・速度変更・早送り（テストでは一瞬で 1 ラウンドを終える）が自然にできる。イベントの順序が `(時刻, 種類, 連番)` で一意に決まる
- 短所: スケジューラを自作する必要がある（小さい）

### 案 B: 固定間隔のフレーム（例: 50ms ごとに全部を更新）

- 長所: 実装が単純
- 短所: フレームの中での処理順が曖昧になりやすい。航行時間などがフレームの間隔に丸められる

### 案 C: 実時間のタイマー（`time.AfterFunc` など）

- 長所: 書きやすい
- 短所: 決定性がなく、テストに実時間がかかる

## 決定

案 A。Raft の tick も「ゲーム内 500ms ごとの `RaftTick` イベント」としてスケジューラに載せる。サーバーのセッションループが、実時間の経過に速度を掛けた分だけ `RunUntil` で進める。

## 結果

- 良いこと: 1,000 シードのシミュレーションテストが数秒〜数十秒で終わる。速度を変えても結果が同じ
- 悪いこと: シミュレーションのパッケージで実時間・goroutine を使わないという規約を守り続ける必要がある（`forbidigo` で検出）

## 差し替えるときの影響範囲
