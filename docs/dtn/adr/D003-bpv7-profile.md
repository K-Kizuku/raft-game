# ADR-D003: BPv7 は単一宛先・非フラグメントのプロファイルを自前で書き、CBOR だけライブラリを使う

- 状態: Proposed（DTN-01 #158 でオーナーが確かめて Accepted にする）
- 日付: 2026-11-08
- 決めた人: オーナー
- 関連: #163（DTN-06）、[bpv7-profile.md](../bpv7-profile.md)、[RFC 9171](https://www.rfc-editor.org/rfc/rfc9171.html)

## 背景

島と船の間を動く手紙を、BPv7（RFC 9171）の Bundle にする。ゲームの仮想時間には同期した時計がない。Raft のメッセージの中身は書き換えない。BPv7 の符号化を、Go（Actor）と TypeScript（Cloudflare の Actor Host）の両方に持ちたくない。

## 検討した選択肢

### 案 A: CBOR は既存のライブラリ、BPv7 の構造は自前

- 長所: CBOR の細部（整数の最短の符号化・長さ確定）をライブラリに任せられる。BPv7 は使う範囲だけを書けばよく、範囲を文書で正確に言える
- 短所: BPv7 の構造・CRC・EID の誤りは自分で防ぐ（固定の fixture と fuzz で確かめる）

### 案 B: すべて自前

- 短所: CBOR の符号化の不具合の危険が増える。作業量が増える

### 案 C: 既存の Go の BPv7 実装（dtn7-go など）を使う

- 短所: 版・ライセンス（dtn7-go は GPL-3.0 で、Apache-2.0 のこのリポジトリにリンクしにくい）・保守の状況の調査が先に要る。使わない機能が多い

### 時刻の対応

- **案 T1: 作成時刻を 0 にし、仮想時間の経過を Bundle Age ブロックで運ぶ**（RFC 9171 は、作成時刻が 0 のとき Bundle Age ブロックを必須にしている）
- 案 T2: 仮想時間を DTN time の欄に入れる（2000 年からの実時間という意味を壊す）

## 決定

**案 A と T1**。

- CBOR は `fxamacker/cbor/v2`（MIT）。`NOTICE` に記録する
- EID は `ipn` 方式（島のノード番号は Raft のノード ID）
- Bundle Age は送り出す Actor（Go）が更新する。TypeScript の Actor Host は bytes を解釈せず、保存と運搬だけをする
- 範囲外のブロック・フラグ・断片は、フラグに関係なく断る（閉じた系なので RFC より厳しくする）

## 結果（この判断によって起きること）

- 良いこと: BPv7 の符号化が Go の 1 か所だけになる。プロファイルの範囲が文書と検査で一致する
- 悪いこと・受け入れるリスク: 外部の DTN 実装と相互に接続できることまでは保証しない（fixture での相互運用の確認は、できる範囲で行う）

## 差し替えるときの影響範囲

`server/internal/dtn/bpv7`・[bpv7-profile.md](../bpv7-profile.md)。拡張ブロックを足すときは §6 の検査も変える。

## 見直すきっかけ

- 外部の DTN の実装（µD3TN など）と実際につなぎたくなったとき
- Fragmentation が要るほど大きな Raft のメッセージ（スナップショットなど）を運ぶとき
