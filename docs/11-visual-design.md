# ビジュアルデザインの方針

画面の見た目（配色・文字・余白・全体の統一感）の約束です。T-420 で土台（この文書・デザイントークン・下地のスタイル・見本の画面）を作り、各画面の作り込みは後続のタスク（マップ T-421・ゲーム画面の部品 T-422・リザルト T-423・タイトルなどの画面 T-424・大きな画面と読みやすさ T-425）が、ここに書いたトークンを使って行います。

- トークンの正本: [`web/src/ui/theme/tokens.css`](../web/src/ui/theme/tokens.css)（CSS）と [`web/src/ui/theme/tokens.ts`](../web/src/ui/theme/tokens.ts)（TypeScript。値の一致はテストで確かめる）
- 下地のスタイル: [`web/src/ui/theme/base.css`](../web/src/ui/theme/base.css)
- 関係する要件: NFR-10（アクセシビリティ）。画面の構成は [ゲームデザイン §7](./04-game-design.md)

## 1. 方向性 — 温かい絵本・海図風

- **生成りの紙**のような地色の上に、**水彩風の青い海**と**丸みのある島**を描く。古い海図を絵本の画家が描き直したような雰囲気
- モチーフは**手紙・切手・封筒・消印**。郵便の赤と封筒の金を差し色にする
- やさしく親しみやすく。対象には非エンジニアを含むので、技術的な冷たさ（黒い背景・等幅のログ風の表示）は、エンジニアモードの中だけにとどめる
- **嵐だけは対比を出す**。暗い雲と雨で、穏やかな紙と海の世界に「分断」が起きたことを一目で分からせる
- デモは**大きな画面（プロジェクター 16:9）**で見せる。遠くからでも読める大きさと、淡すぎない色の差を保つ

## 2. 配色

| トークン | 値 | 用途 |
|---|---|---|
| `--color-paper` | `#f6efdf` | 画面の地色（生成りの紙） |
| `--color-paper-deep` | `#efe4cc` | パネル・カード |
| `--color-ink` | `#3b3a36` | 本文 |
| `--color-ink-muted` | `#6b6457` | 補足 |
| `--color-sea-light` / `--color-sea-mid` / `--color-sea-deep` | `#bfdde6` / `#8ec5d6` / `#3c6e8f` | 海（水彩風の濃淡）。`--color-sea-deep` はリンクとフォーカスの輪にも使う |
| `--color-land` / `--color-land-green` | `#d9c79a` / `#8fb07a` | 島（砂浜と緑） |
| `--color-postal` | `#c0503a` | 郵便の赤（主ボタン・強調・依頼） |
| `--color-gold` | `#e0a84f` | 封筒の金（★・確定・成功の強調） |
| `--color-storm` / `--color-storm-deep` | `#5a6472` / `#2f3640` | 嵐の雲・雨 |
| `--color-success` / `--color-warning` / `--color-danger` | `#5b9a68` / `#e0a84f` / `#c0503a` | 状態 |
| `--color-danger-text` | `#8b4738` | 失敗・期限切れの文字（`--color-danger` 60% に墨を混ぜた色。紙で 5.9:1・パネルで 5.4:1）。T-425 で追加 |

- **郵便の赤は、案の `#C8553D` から `#c0503a` に少し暗くした。** 白い文字とのコントラスト比が `#C8553D` では 4.35:1 で 4.5:1 に届かないため（`#c0503a` は 4.72:1）。`--color-danger` も同じ値にそろえた
- 16 進の値は小文字で書く（Prettier の書式に合わせる。大文字と同じ色）
- **島の色はステージ定義（`islands[].color`）のものを使い、トークンにしない。** 島ごとの色は島の識別に使うので、画面の配色とは分けて管理する
- PixiJS のマップは色を数値で使う。`colorNumber("--color-sea-mid")`（`0x8ec5d6`）か `palette.seaMid` で引く
- 状態の色だけに頼らない。成功・警告・失敗は、文字やアイコンの形でも伝える（§8）
- **トークンに入れるかの決め方（T-425）**: T-421〜T-424 の部品が「トークンに無い色」としてローカルの変数に置いた色のうち、**2 か所以上で使う色だけ**をトークンにした。失敗の文字の色（HUD・島の詳細・フェリー操作・船の一覧・セッションの知らせの 5 か所）を `--color-danger-text` にした。1 か所だけで使う色（帯の縞・封筒の線・嵐の灰の地・行き先宛ての札・依頼の ★・リザルトの文字の色・マップの水彩のにじみ `MAP_DERIVED_COLORS` など）は、その部品の CSS（`color-mix()`）・`style.ts` のローカルの値のまま残す。どれもトークンを混ぜて作り、16 進の色を直接書かない
- **夜の配色（T-425）**: エンジニアパネルとデモ操作のキーは、デモで目立つよう「夜の海図」にする。地は `--color-storm-deep`（不透明）、文字は `--color-paper`（10:1 以上）、補足と罫は `--color-sea-light`・`--color-sea-mid`、代表（Leader）と古い情報の強調は `--color-gold`。新しい色は足さず、既存のトークンの組み合わせで作る

## 3. 文字

| トークン | 値 |
|---|---|
| `--font-body` | `"Hiragino Maru Gothic ProN", "BIZ UDPGothic", "Zen Maru Gothic", "Yu Gothic", system-ui, sans-serif` |
| `--font-number` | `ui-rounded, "SF Pro Rounded", var(--font-body)`（使うときは `font-variant-numeric: tabular-nums` と組にする。クラス `.text-number`） |
| `--font-size-body` | 16px（本文の基準） |
| `--font-size-h3` / `--font-size-h2` / `--font-size-h1` | 20px / 24px / 32px（見出し） |

- 丸みのある日本語の書体を、端末にあるものから選ぶ。**Web フォントは読み込まない**（外部への通信と容量を避ける）
- 時間・スコアなどの数字は `.text-number` で桁をそろえ、変わっても横に揺れないようにする
- **大きな画面（`min-width: 1600px`）では、文字の大きさのトークンを 1.25 倍にする**（本文 20px、見出し 25・30・40px）。部品は px を直接書かず、トークンか `em` で大きさを決める。`rem` はルートの文字の大きさ（ブラウザの既定の 16px）のままで 1.25 倍にならないので、文字の大きさには使わない（T-425 で、マップの島のボタン・分断の凡例の `rem` を、ゲーム画面の CSS から `--font-size-body` の倍数に上書きした）
- HUD の残り時間・スコア・確定の数は `--font-size-h2`（24px、大きな画面で 30px）
- マップの文字（PixiJS の `Text`）は、画面の幅から決める倍率 `labelScale(screenWidth)`（`web/src/game/model/art/labelScale.ts`。1280 以下で 1、1920 以上で 1.3、その間は直線）で大きくする。島の名前の大きさは `labelFontSize`（13px）× 絵の拡大率 × `labelScale`。倍率は画面の大きさが変わったときだけ計算する
- 行の高さは本文 1.6、見出し 1.3

## 4. 余白

| トークン | 値 |
|---|---|
| `--space-1` 〜 `--space-6` | 4px・8px・12px・16px・24px・32px |

- 余白はこの 6 段から選ぶ。部品の中は `--space-2`〜`--space-4`、部品と部品の間は `--space-4`〜`--space-6` を目安にする
- 押せるもの（ボタン・島）は、指でもポインターでも押しやすいよう、高さ 44px 以上を目安にする

## 5. 角丸

| トークン | 値 | 用途 |
|---|---|---|
| `--radius-s` | 6px | 小さな札・入力欄 |
| `--radius-m` | 12px | ボタン・色の見本 |
| `--radius-l` | 20px | パネル・カード・吹き出し |

角は丸くする（とがった角は使わない）。島や吹き出しのやわらかさと合わせる。

## 6. 影

| トークン | 値 |
|---|---|
| `--shadow-paper` | `0 1px 0 rgba(59, 58, 54, 0.08), 0 4px 12px rgba(59, 58, 54, 0.12)` |

- 影は「紙が重なっている」ことを表す 1 種類だけ。墨の色を薄くした影で、黒い影は使わない
- 押したボタンは影を消して、紙が押し込まれたように見せる

## 7. アイコンと絵の約束

- 線は太め・角は丸く、水彩の塗りのような少しむらのある色にする。写真や写実的な絵は使わない
- 手紙の種類は**色と形の両方**で区別する（NFR-10。`web/src/ui/letters/`）
- 封筒・切手・消印・★を、確定・成功・依頼の印に使う。★と確定は封筒の金、依頼は郵便の赤
- 画像を追加するときは 1 つ 20KB 以下を目安にし、なるべく SVG か CSS で描く。紙の質感は CSS のグラデーションで出す（画像を使わない）
- 郵便局長の絵・タイトルの絵は人が作る（#131）。それまでは島の色の丸と頭文字で代える
- **学べることの図（T-433）**: `web/src/ui/art/learning/`。ステージ定義の `learning` のキーごとに、小さな島（代表は金の★、退いた代表・数に入らない島は淡く）・封筒・✓（金の丸）・台帳・海図の点線の航路・嵐の雲で 1 場面を描く。文字は持たず（aria-hidden）、説明は隣の文が伝える。線は `vector-effect: non-scaling-stroke` で小さくしても同じ太さにする。動き（封筒と定期便）は `prefers-reduced-motion: reduce` で止める
- **favicon と OGP の画像（T-430）**: `web/public/` の `favicon.svg`（丸い海の枠に封筒。色はトークンと同じ 16 進）・`favicon-32.png`・`apple-touch-icon.png`（180×180）・`og-image.png`（1200×630。タイトルの絵の部品を並べ直したもの）。`web/index.html` が link・OGP の meta で指す。PNG は、元の HTML（`web/brand/`。ビルドに入れない）から `scripts/render-brand-images.sh`（ヘッドレスの Chrome）で作り直す。タイトルの絵の部品を変えたら `web/brand/og-image.html` も合わせて直す

## 8. 画面ごとの雰囲気

| 画面 | 雰囲気 |
|---|---|
| タイトル・ステージ選択・遊び方 | 紙の地色に、海図の端のような余白と切手のような札。ゆったりとした余白 |
| ゲーム画面（マップ） | 水彩の海（`--color-sea-light`〜`--color-sea-deep`）に、丸い島（`--color-land`・`--color-land-green`＋島の色）。航路は海図の点線 |
| ゲーム画面（HUD・パネル） | マップの上に重なる紙のパネル（`--color-paper-deep`・`--shadow-paper`・`--radius-l`）。数字は `.text-number` |
| 通知 | 便箋のような吹き出し（`.speech-bubble`）。郵便局長が話しかける |
| リザルト | 封筒を開けるような明るさ。★は封筒の金 |
| エンジニアモード | 唯一の「計器」らしい画面。「夜の海図」の配色（§2）のパネルの中に、点線の罫の表と、桁のそろう数字を並べる。代表の行と古い情報は封筒の金 |
| デモ操作のキー | 発表者のための、画面の下の端の細い帯。夜の配色に、紙の札のキー（紙の地に墨の文字・下の縁を厚く） |

## 9. 嵐と花火の表現

- **嵐**: 嵐の航路の上に、`--color-storm`〜`--color-storm-deep` の暗い雲と、斜めの雨の線を重ねる。航路は点線にし（[ゲームデザイン §7](./04-game-design.md)）、色だけでなく形でも止まっていることを示す。予報の通知も、雲の色の縁取りで穏やかな通知と区別する。嵐の雲の上に文字を置くときは白い文字にする（`--color-storm-deep` と白のコントラスト比は 12:1 以上）
- **花火**: ★2 の花火大会は、封筒の金（`--color-gold`）と郵便の赤を中心に、紙吹雪のような丸い粒で描く。嵐との対比で、夜空ではなく紙の上で開く絵本の花火にする
- どちらの動きも、`prefers-reduced-motion: reduce` のときは止めるか、動かない絵（雲の形・花火の絵）に置き換える
- **依頼の確定**（T-435）: 依頼が確定すると、代表の島から依頼した島へ封筒の金の光る線が伸び、依頼した島に紙吹雪（金・郵便の赤・緑・海の色・紙の色）が 1〜2 秒散る。`prefers-reduced-motion: reduce` のときは、伸ばさずに光る線だけを出して消す（紙吹雪なし）

## 10. アクセシビリティ

- **文字のコントラスト比は 4.5:1 以上**（NFR-10）。次の組み合わせはテスト（`web/src/ui/theme/tokens.test.ts`）で確かめる
  - 本文と地色（`--color-ink` と `--color-paper`）: 9.9:1
  - 本文とパネル（`--color-ink` と `--color-paper-deep`）: 9.0:1
  - 主ボタン（白と `--color-postal`）: 4.7:1
- 補足の文字（`--color-ink-muted`）は、地色・パネルの上で 4.5:1 以上（5.1:1・4.6:1）。それより淡い色を文字に使わない
- 色だけで情報を伝えない（嵐は点線と雲、状態は文字やアイコンも添える、リンクは下線）
- フォーカスの輪は、`:focus-visible` のときだけ出す 3px の輪（地から 2px 離す）。消さない。トークン `--focus-ring-width`・`--focus-ring-offset`・`--focus-ring-color` で決め、部品の CSS で別の色・太さの輪を書かない（T-425 で、部品ごとに書いていた輪を消した）。色は地によって変える
  - 紙の地・パネル: `--focus-ring-color`（深い海の青。紙で 4.7:1・パネルで 4.3:1）
  - 海の上（マップの上の島のボタン・エンジニアパネルの切り替え・タイトルのメニュー）: `--focus-ring-color-on-sea`（墨。海で 6:1 以上）
  - 夜の配色の上（エンジニアパネルの中）: `--focus-ring-color-on-night`（封筒の金。6:1 以上）
  - 郵便の赤の主ボタン: 輪はボタンの外の地に出るので、その地の色に従う
  - 線を太くする設定（`prefers-contrast: more`）では 4px にする
- **使っている色の組の一覧**を `web/src/ui/theme/contrast.test.ts` で確かめる（T-425）。文字は 4.5:1 以上、大きな文字（24px 以上か太字 18.66px 以上）と文字でない部品（線・縁・フォーカスの輪）は 3:1 以上、プロジェクターで読む HUD の数字と本文・夜の配色の文字は 7:1 以上。半透明の地は、下の地に重ねた後の色で比べる。部品の色を変えたら、この一覧も同じ PR で直す
- `prefers-reduced-motion: reduce` のとき、下地の動き（ボタンの浮き沈み）を止める。後続の部品の動きも同じにする
- 大きな画面では文字を 1.25 倍にする（§3）
- `prefers-reduced-motion: reduce` のとき、マップ（波・雨・船の揺れ）・リザルトの★と花火・タイトルの絵の動き・お知らせ・開会式・チュートリアルの動きが止まる（T-425 で通しで確かめた）
- 出航を押してからゲームが始まるまで（接続の準備中・接続中）は、マップの中央に出港の絵（`web/src/ui/art/DepartureArt.tsx`。港の島から郵便船が出ていく）と「出航の準備をしています…」の紙の札を出し、つながったら消す。つながらないときは絵を消して、隅の札にエラーの文言を出す。`prefers-reduced-motion: reduce` のときは、船を港の少し沖に止めて描く（T-436）

## 12. 大きな画面のきまり（T-425）

デモは大きな画面（プロジェクター 16:9）で、少し離れた観客に見せる。1920×1080 と 1280×720（ブラウザの全画面、`devicePixelRatio` 1 と 2）で次を守る。

| きまり | 1920×1080 | 1280×720 |
|---|---|---|
| ゲーム画面のページ全体の縦のスクロール | 出さない | 出さない |
| マップの大きさ | 画面の幅の 55% 以上・高さの 55% 以上 | 高さの 45% 以上 |
| 本文 | 20px 以上 | 16px 以上 |
| HUD の残り時間とスコア | 28px 以上（30px） | 24px |
| マップの島の名前 | 16px 以上 | — |

- **ゲーム画面**（`web/src/app/game/GameScreen.css`）は画面の高さちょうど（`100dvh`）に収める。グリッドの並び（状況・マップ・島の詳細・フェリー操作）は変えない。マップの行は `minmax(45vh, 1fr)`（`min-width: 1600px` では 55vh）、フェリー操作の行は中身の分だけ（上限はマップの行の残り）で、入りきらないときはフェリー操作と島の詳細の中で巻き取る。画面が 36rem より低い（16:9 でない画面・ブラウザの拡大）ときだけ、ページの縦のスクロールを出す
- **島の詳細の列の幅**は `clamp(18rem, 24vw, 30rem)`（変数 `--game-island-width`）
- **フェリー操作**は、幅 1200px 以上で 3 列（左: 船の名前・港と積み荷・結果の文、中: 行き先、右: おまかせ・出航）。行き先と出航のボタンが領域の上の方に来る。左から右の順は要素の順番（読み上げ・Tab の順）と同じ
- **重ねる部品の置き場所**（互いと HUD・出航のボタンを隠さない）

  | 部品 | 置き場所 |
  |---|---|
  | お知らせ | マップの右上（幅はマップの半分まで。右下の切り替えに届かない高さまで） |
  | 分断の凡例・チュートリアル | マップの左上 |
  | 島のボタン | マップの左下 |
  | エンジニアパネルの切り替え | マップの右下 |
  | エンジニアパネル | 開いている間は右の島の詳細の列（島の詳細の代わり。列を `clamp(22rem, 37vw, 44rem)` に広げ、マップを覆わない）。中は「ノード一覧」「Raft ログ」「Progress」「手紙」のタブ（← → で切り替え）で、巻き取らずに収める（Raft ログは新しい 8 件まで。T-438） |
  | 嵐の紹介 | マップの下の方の中央（島のボタン・切り替えより上） |
  | デモ操作のキー | 画面の下の端の帯（ゲーム画面が帯の分だけ下の余白を取る） |
  | 開会式 | 画面の中央（始まりのときだけ） |

  マップに合わせる部品は、CSS のアンカー配置（`anchor-name: --game-map`・`--map-islands`。GameScreen.css）を使う。アンカー配置が使えないブラウザでは、`@supports` の外の固定の位置（画面の右下・上の端）に置く

- **ゲームの外の画面とリザルト**は、`min-width: 1600px` で `.app-screen` の最大の幅を 72rem に広げ、中央に置く（タイトルのメニューは 46rem）
- 1280×720 用の別の切り替え（`max-height` など）は置かない（上の行の高さの指定で収まる）
- 島の色（ステージ定義）が明るくても暗くても見分けられるよう、島の色の丸・お知らせの顔・ノードの丸は、紙の色の縁と墨（夜の配色では紙の色）の細い輪で囲む（ステージ定義の色は変えない）

## 13. プロジェクターの確認の一覧（デモの前）

デモの会場で、本番と同じ画面（プロジェクター・ブラウザの全画面）で確かめる。

1. ブラウザを全画面（F11・⌃⌘F）にし、拡大を 100% にする。画面の大きさが 1920×1080 か 1280×720 か確かめる（開発者ツールで `innerWidth`・`innerHeight`）
2. タイトル → ステージ選択 → 紹介 → ゲーム画面 → リザルトと進め、どの画面でも文字が会場の後ろから読めるか（本文・HUD の数字・マップの島の名前）
3. ゲーム画面で、ページ全体が縦に巻き取れない（出航のボタンが画面の中にある）か。船を選んで、行き先と出航のボタンが見えるか
4. 嵐のとき、マップの暗い雲と点線の航路・✕が、プロジェクターの淡い色でも海と見分けられるか
5. エンジニアパネルを開いて（E）、お知らせ・島のボタン・出航のボタン・HUD が隠れないか。夜の配色の文字が読めるか
6. デモ操作のキーの帯が、画面の下の端に 1 行で出ているか（フェリー操作を隠していないか）
7. キーボードの Tab で、フォーカスの輪が紙・海・夜のどの地の上でも見えるか
8. 会場の明るさで、紙の地（`--color-paper`）とパネル（`--color-paper-deep`）の差が見えるか。見えにくければ、プロジェクターのコントラストを上げる（色のトークンは変えない）
9. 動きを減らす設定の端末なら、マップの波・雨・花火が止まっていて、絵が崩れていないか

## 14. 後続のタスクの判断の反映（T-425）

- T-421（マップ）: マップの絵の色は `MAP_STYLE.colors`（トークンの数値）と `MAP_DERIVED_COLORS`（トークンを混ぜた 2 色）。にじみと予報の雲の色はマップだけで使うので、トークンにしない
- T-422・T-426（ゲーム画面の部品）: 失敗の文字の色を `--color-danger-text` にまとめた。帯の縞・封筒の線などはローカルのまま（§2）。押せないボタンは `opacity` を使わず、破線の枠と `--color-ink-muted` で示す
- T-423（リザルト）: ★の押印と花火は、動きを減らす設定で止める（花火の空は出さない）。リザルトの文字の色（達成・時刻）はローカルのまま
- T-424（タイトルなど）: タイトルの絵の上のメニューは、フォーカスの輪を墨にする（水彩の海の上で見えるように）
- T-425a（重ねる部品）: エンジニアパネルとデモ操作のキーは、T-425a の「紙の航海日誌」から、デモで目立つ「夜の海図」の配色に変えた（クラス名・`data-*`・文言は同じ）。チュートリアル・嵐の紹介は、HUD を隠さないよう、マップに合わせて置く

## 15. 基準の画面とスクロールの方針（T-429・T-429b）

**基準の画面は 1470×860**（オーナーの Mac のブラウザの表示領域）。

**ゲーム中の画面・ほんの少しだけはみ出す配置はスクロールさせない。リザルトのように情報が多い画面はスクロールしてよい**（T-429b のオーナーの判断）。

- ゲーム中にスクロールが要ること、`1.2vh` のようにほんの少しだけはみ出してスクロールが要ることは、ストレスになるので避ける。こうした画面は、1470×860 で `document.documentElement.scrollHeight > innerHeight` にならないようにする（パネルの中の巻き取りは可）。情報は減らさず、並べ方で収める
- リザルトのように、複数の内容があり情報が多い画面は、もともとスクロールしてよいくらいの情報量なので、画面全体のスクロールを許す（無理に 1 画面へ詰めない）
- 洗い出しの対象: タイトル・ステージ選択・ステージ紹介（Stage 1〜3）・遊び方・クレジット・設定・ゲーム画面（エンジニアモードを開いた状態も）・リプレイ。スクリーンショットは `scripts/screenshot.sh --size 1470x860` で撮る
- 長い一覧（フェリー操作・島の詳細）は、そのパネルの中だけで巻き取る。エンジニアモードはタブに分けて巻き取らない（§12）
- 1280×720 では、縦のスクロールが出てもよい（大きく崩さない。ゲーム画面は §12 のとおり出さない）

| 画面 | 収め方（幅 1024px 以上。遊び方は 1280px 以上） |
|---|---|
| ステージ選択 | 画面の枠を広げ（最大 96rem）、カードを 1 行に並べる（3〜4 枚）。紹介文は全文を出す |
| ステージ紹介 | 島の紹介と学べることを横に並べる（1:1。T-433 で学べることに図を足したので 3:2 から変えた）。学べることは右の列の高さいっぱいに置き、「出航する」と戻るリンクは左の列の島の紹介の下に置く |
| 遊び方 | 6 つの節を 3 列 × 2 行に並べる。番号と絵は節の見出しの左に小さく置き、文は節の幅いっぱいに流す |
| クレジット | 2 列の段組み（左: オープンデータ、右: ソフトウェアと素材） |
| ゲーム画面 | §12 のまま（画面の高さちょうど。フェリー操作と島の詳細の中で巻き取る） |
| リザルト | 収めない（T-429b で T-429 の前の配置に戻した）。紙のカードに節を縦に 1 列で並べ、画面全体をスクロールしてよい |
| リプレイ | 再生中はゲーム画面と同じ。リザルトの段は、リザルトの紙と「別の入力ログを選ぶ」を合わせて画面の高さに収める |

## 11. 実装

- アプリの入口 `web/src/app/App.tsx` で `web/src/ui/theme/index.ts` を 1 回だけ読み込む（トークンと下地が全体に効く）
- 下地（`base.css`）は、ほかの部品の見た目を変えないよう、要素への規則（`body`・見出し・リンク・フォーカスの輪）を `:where()` で詳細度 0 にしている。部品が自分の CSS で上書きできる
- 共通の部品はクラスで使う
  - `.btn`（紙の札のボタン）・`.btn-primary`（郵便の赤のボタン。白い文字）
  - `.paper-panel`（パネル・カード）
  - `.speech-bubble`（通知の吹き出し）
  - `.text-number`（数字）・`.text-muted`（補足）
- **見本の画面**: 開発のとき（`make dev`）に、URL に `?theme-preview` を付けて開く（例: `http://localhost:<DEV_WEB_PORT>/?theme-preview`。ポートは `make dev-env`）。色・文字・ボタン・パネル・吹き出し・余白・角丸の見本が並ぶ。`import.meta.env.DEV` のときだけ遅延読み込みするので、本番のビルドには入らない
- トークンの値を変えるときは、`tokens.css` と `tokens.ts` とこの文書を同じ PR で変える
